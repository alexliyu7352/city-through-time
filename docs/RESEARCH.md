# 研究規約：怎麼為一座城市寫《一城春秋》

目標：用戶只給城市與起始年代。年代表、貫穿線、幾何、字幕文字全部由代理自己查，而且每一條都能回到來源。

## 1. 選材：什麼值得成為一站

歷史的厚重感來自這座城自己經歷的轉折，不是來自考古發現的數量。每一站必須回答「這座城在這裡變了什麼」：

- **地位**：建城、遷都、設市、升格、分區、劃歸。
- **產業**：一個產業的興起、鼎盛、衰落、轉型（咸陽：紡織城 → 電子城 → 國棉改制 → 西部屏谷）。
- **連接**：橋、鐵路、機場、地鐵、區號並網、和鄰城的同城化。
- **城市形態**：新區、新城、湖、河道，城市朝哪裡長。
- **興衰**：繁榮、戰火、衰敗、重建。

檢驗：拿掉這一站，觀眾對「這座城怎麼變成今天」的理解會少一塊嗎？不會就不成站。

**先找出這座城和別的城不一樣的地方，再定結構。** 定站之前先回答五個問題，答案決定開場、那場獨特的戲和結尾：
1. 名字從哪來：開場就交代它（咸陽：九嵕山在北、渭水在南，山水俱陽）。
2. 有什麼別的城沒有的規劃或地理：給它一場戲（SKILL.md 演出文法 8；咸陽：秦咸陽法天象地、咸陽原的台地）。
3. 城址動過沒有、怎麼動的：沒動和搬過都是故事（成都 2000 多年沒動過，咸陽搬了好幾次）。
4. 近現代給了它什麼身份（咸陽：紡織城、電子城、空港、西咸一體化）。
5. 有沒有一件從頭到尾都在的東西（第 2 節的貫穿線；可選的象徵物見 SKILL.md 步驟 3）。

站表不要照通用的朝代順序（新石器→秦→漢→唐→明→鐵路）填空，每一站都要是這座城自己的東西。

**從這座城自己的角度看每個轉折**：不只記發生了什麼，還要想這座城的人盼過什麼、失去過什麼，一件事對它是喜是憂。
例：咸陽和西安太近、歷史糾纏太深。2006 年 029 並網後，咸陽人盼著兩城合一、恢復昔日榮光；2017 年西咸新區交西安代管，
最精華的一塊地歸了西安，合併也就此不會發生。所以 2017 那一句是惆悵，不是中性的行政變更。這些心事決定講述者的情緒，
也決定結尾怎麼收（咸陽：兩城沒有合併，卻長在一起）。

**考古與陵墓**：只有在它改變了城市本身時才成一站，例如新城建設和遺址保護的衝突、遺址成了城市的公園或地標。發掘本身、出土數字、
陵墓都不單獨成站，最多是某一站裡的一句。古代部分講城市時，考古是「怎麼知道」的出處，不是故事本身。

**每站要能畫在模型上**：一個範圍（區、新城、廠區、保護範圍）、一條線（橋、地鐵、鐵路）或一個點；畫不出來的事實放進字幕，不成站。

咸陽 1975–2026 的例子：彩虹廠（電子城）、設市與分區、機場、國棉改制、咸陽湖、029 並網、秦漢新城與遺址保護範圍、西咸新區、
地鐵進咸陽、兩城一線、「十五五」與西部屏谷。曾經的反例：府庫裡的火、機場下的古墓、新公布的陵墓（考古細節，不是城市的轉折，用戶刪掉）。

## 2. 貫穿線（anchor）

找一件從起點一直存在、今天仍看得到的東西，讓觀眾在各個時代認出同一座城：一條河與它的渡口、一塊台地、一條軸線、一座城門、
一個延續的產業。成都的範本：金沙遺址——3000 年前埋下，2001 年施工時挖出，太陽神鳥成了城徽（這裡考古成立，是因為它變成了城市的象徵）。
評分順序：
1. 它的變化本身就是城市的轉折（遷移、改建、廢棄、重新使用），而且每次都有明確年份。
2. 在模型範圍之內（否則只能當序幕或用邊緣指示牌）。
3. 來源是官方、學術或主流媒體原文，不是旅遊網站。
4. 回聲會重複更好（例如咸陽：渭河的渡口、橋、湖與地鐵一再改寫兩岸的關係）。

## 3. 年代表

最後一列必須是當前年份（今年）：找最新的政府工作報告、統計公報或本年度大事，故事要講到現在。

從起始年代到今天，每條：年份（公元前用負數）、事件、第一語言一句（漢字 ≤22 字；其他書寫系統照 `i18n/<代碼>.yaml` 的上限）、
第二語言一句（英文 ≤70 字元；英語城市只有這一句）、來源 URL、原文引文、狀態標記。
狀態：[OK] 開過原文；[SEC] 只有維基或搜尋摘要；[WEAK] 旅遊／聚合站；[EST] 估算。
只有 [OK] 和 [SEC] 可以上屏；[SEC] 的關鍵年份要再找一個來源或在 FACTS.md 註明。兩個來源衝突時兩個都記，畫面用較保守的說法。
這些要求約束的是代理自己的研究，管的是事實。講述者的感受、評價和聯想不需要出處（那是作品的聲音）；但不能把感受寫成新的事實。
用戶自己寫的文案（本地歷史、家族記憶、沒上網的資料）照用，不要求出處；與已查到的資料矛盾時才提出。
用戶轉貼的別處材料（別的代理給的清單、網路文章、年表）不算用戶自己的文案：它們是線索，照本節逐條回到原文，查不到的不上屏；
查到的說法和轉貼的不一樣，照查到的寫，並告訴用戶。裡面建議的做法也要實測才採用（咸陽：用戶轉來的現代站表查證後收了三件半：
「紡織一條街」查無出處；「西部顯示谷」其實是「西部屏谷」；「2019 地鐵時代」要分成 2019 年過界、2023 年進主城兩步講）。

## 4. 幾何

先查 OSM：`historic=*`、`site_type`、`archaeological_site`、`tomb`、`citywalls`、保護區多邊形（pipeline/osm.py 的 historic 主題已抓）。
有輪廓就用輪廓（`osm_polygons:` / `mounds: osm:`），FACTS.md 記 way id。
沒有輪廓：用文獻描述畫示意多邊形（`polygons:`），畫面標「示意」。沒有坐標的點只在字幕提，不打釘標。
字幕點名的範圍（行政區、新區、新城、廠區、保護範圍）要找邊界：OSM 行政界線、官方規劃圖、組成它的鄉鎮街道；找不到就從四至描述畫示意。
全部寫進 `research/<主題>_areas.geojson`（properties.id、status、source），研究檔逐項記來源與做法。
土丘、台基等今天仍在的土方用 `mounds:` 建成真實幾何（底面取 OSM 輪廓，高度取文獻，無記載者取通例並註明）。

## 5. 研究子代理的任務書要點

- 任務書先寫第 1 節的選材規則：找城市的轉折（地位、產業、連接、形態、興衰），考古與陵墓只在改變了城市時才列。
- 指定輸出檔與章節：年代表、坐標表、錨點候選排序、數字、未核實清單。
- 要求每條附 URL 與原文；要求區分原文與 fetcher 摘要（[PARAPHRASE]）。
- 政府網站常常連不上：讓它記下 URL，主代理再試或改用新聞轉載。
- 主代理必須自己再核：錨點事件、所有上屏年份、人物與地名，以及句子裡差一個詞就錯的限定詞（「國際」「首個」「進市區」）。
  沒附原文的條目一律當作未核實（咸陽：另一個代理給的 15 條裡，咸陽湖蓄水年份、地鐵二期「進市區」、機場「國際」二字、「中國第一隻彩管」
  都有錯或沒有出處）。
- 指定輸出的路徑在 `cities/<slug>/research/`（筆記、報告、出處原文都是，音樂研究的分頭筆記放 `research/music_notes/`），跟城市一起進 git。
  寫成摘要之後，原來的筆記照樣留著：摘要裡沒有逐條的出處和原文（咸陽的五份配樂研究筆記曾因為「已經有總報告」被當成用不到刪掉）。

## 6. 字幕與讀數的寫法

- 字幕一條一個事實，第一語言在上、第二語言在下（SKILL.md 10c）；不確定的寫「傳說」「可能」「示意」。
- **數字一律用阿拉伯數字 0–9，每種語言都一樣**：年份、日期、時刻、數量、度量、百分比、序號（1 號線、第 3 期）。寫旁白時就這樣寫，不是寫完再改：
  不用中文數字（一九八三年、八百八十二）、日文漢數字、阿拉伯-印度數字（٠١٢٣）、波斯數字、天城文（०१२）、泰文（๐๑๒）等各語系自己的數字字元，
  也不用全形數字（１２３）。片子要給不同語言的觀眾看，數字是共通的部分。
  例外只有專有名詞與固定說法：計畫或事件的名稱（「十五五」）、成語與慣用語（一座又一座、一層一層）、引文（火三月不滅），
  以及**歷史紀年照原文**：帝王年號紀年（洪武四年、乾隆十六年、武德二年）、干支紀年、其他曆法的紀年。不要換算成公元寫進旁白：
  公元年份已經在畫面左側的年份面板上，旁白保留原來的紀年，才有那個時代的味道。
  例外寫進 city.yaml 的 `film.copy.keep`，文案檢查就不再提。
- 讀數（左欄）只放一個大數字（年份計數器或一個統計數）、一行標籤、一行來源。
- 讀秒規則：中文字數÷4.5 + 英文字母÷15 + 1.5 秒，最少 1.8 秒；寧可把片拉長，不要刪事實。

## 7. 時代感：先查那個時代實際有什麼

音樂、服飾、器物、建築細節、想像圖的提示詞，寫之前先研究那個時代、那個地方實際有什麼，分清實證（出土、原典）、推論、現代慣例，
寫進 `research/<主題>.md`，每條附出處。憑印象寫的「古風」多半是時代錯置。
咸陽：配樂第一版憑印象用簫、古琴當城市聲音，秦段用法國號、低音銅管，焚城用二胡；研究後才知道秦有李斯「擊甕叩缶彈箏搏髀」、兵馬俑坑的鼓、
秦公鐘鎛和石磬，銅管、二胡都是時代錯置，簫和古琴在關中找不到本地依據（用戶：「秦時帝都和焚城肯定是鼓是大頭」）。改成鼓當脈搏、塤當記憶、箏當秦聲。
