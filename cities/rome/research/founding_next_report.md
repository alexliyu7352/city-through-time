# 建城期單屋與第一窗口補證

狀態：資料提案，未批准、未編譯、未拍模型圖。只補 `founding_next_*`；舊來源包、正式 FACTS、旁白與城市設定均未修改。753 BCE 繼續是傳統建城標籤，考古樣本仍用鐵器時代／VIII世紀中葉附近的限定語。

## 地理控制的成果與停用條件

已把F01圖1的Magna Mater外框四角對到NF04四個公開牆線角點，以保持比例的二維相似變換解算，**最大殘差約0.94m、RMS約0.67m**。控制點、公式及參數都已保留；這些數值只說明四角擬合，不代表草屋定位達到米級考古精度。

存在兩個實質問題：圖印北箭頭與四角解算北向相差約23.17°；舊包圖1尺端「10m」也無法從現有掃描穩妥確認，右端疑似15，故本輪完全不用此尺定地理比例。沒有為小殘差覆寫北箭頭，也沒有聲稱已修正原刊。

四角法的北側hut輪廓候選中心約 **[12.484847, 41.889219]**。以它距錨點中心約32m、兩種北向差引起約13m位移，加上手讀與錨點辨識允差，提供 **17m工作半徑**；完整外包框在controls。這是覆蓋目前方法分歧的實務範圍，非置信圓或保證的測量界限。**`apply_to_city:false`**：先解北向差，再核A／n.3對照，才可把單屋固定到正式城市。此範圍不給「Casa Romuli本人住宅」定位。

下一輪仍可在獨立局部坐標的形制對照中審主體，並在分期平面上看位置關係；不必等待一個假精確的經緯度。此輪沒有新增地理圖釘或GeoJSON村界。

## Native交付與確切缺項

[shape_proposal](founding_next_shape_proposal.json)的`native_candidate`只含既有`parts`、`prism`、`revolve`資料。下段牆留真缺口、上段牆帶內圈，屋頂是短剖面稜柱加兩個半旋轉端；`atop`沿前一承托件索引，`exaggeration:1`只供未批准的真比例形制比較。所有高度、圈線及相對位移可追回表中公式。沒有北中國builtin hut、`long_hall`替代或城市專用mesh。

此資料**不是可直接載入的完整單屋／city spec**：沒有批准的落位；門廊覆屋、門廊柱高與煙口尚未完成；內部屋架、茅束質地未復原。門廊平面與未定上部已明列，不能由預設值偷偷補齊。

若審查要求嚴格保留「不規則近矩形平面上方的短脊、非半圓端屋頂」，目前native確切缺少的是：**上下輪廓可分別給定的通用loft，或可指定短脊頂線的任意平面屋頂**。`prism.top`只同縮到一點；`revolve`只給規整圓／橢圓端。這是主線通用能力候選，沒有本輪擅改程式的必要。入口真開口已可用現有分段prism表達。

已做的檢核只有JSON資料、來源雜湊及研究算術：閉合線有效、近似屋頂平面覆蓋該閉合線。沒有模型、mesh、geocheck、clipcheck、攝影機或導演驗收結果。重算命令：`uv run python -I cities/rome/research/founding_next_calculate.py`；此程式只重寫本前綴研究資料。
